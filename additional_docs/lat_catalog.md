# lat – Pattern catalogue (canonical source)

This file is the **single source of truth** for the catalogue. `src/seed.sql` is
**generated from it** (see the generator note at the bottom). One entry per row.

**`themes` = closed cognitive-axis vocabulary** (the only permitted values),
used for principled selection (diagnose a problem's structural bias → find
patterns that reframe that axis):

`Causality` · `Agency & control` · `Rank & salience` · `Time & aspect` ·
`Coexistence` · `Perspective & reciprocity` · `Object boundaries` ·
`Evidence & certainty` · `Space & orientation` · `Possession & belonging` ·
`Logic & ambiguity`

`Agency & control` covers the actor's relation to the act (does one exist, was
it willed, who caused it, how many links deep); `Rank & salience` covers which
participant stands in front of the others.

**`tags` = free keywords** (linguistic features and formal mechanics of the
forms: permutation, refrain, meter, compression, …). Whether a pattern carries a
theme follows from its mechanic, not from its category: every language carries
one, and so do most forms — including most techniques and every narrative
structure. Only patterns whose mechanic is purely acoustic, metrical or
typographic carry **no** theme (many metrical feet and fixed forms, plus the
purely procedural techniques `Back-translation`, `Form-switch`, `Lipogram` and
`S+7 (N+7)`); those are reached via `tags`/`category`/`text`.

Input-language contrast selection (prefer lenses that foreground what the
user's own language backgrounds; exclude the source language) is a caller-side
concern, supported by the `exclude_names` filter on `search_patterns`. Nothing
is excluded by default: the filter applies only to the names actually passed,
and it matches by **exact name**, so structural relatives are not caught with
it.

German and English share one blind spot: the causal chain with an acting
subject and a suffering object, and a rank imposed before the subject matter is
considered — the ground covered by `Causality`, `Agency & control` and
`Rank & salience`. For an input in either language, excluding only one of them
recommends that same blind spot straight back, so **exclude both**.

**This cannot be derived from a theme query, which is why it is written here.**
`themes` records what an entry *foregrounds as a lens*, not what it shares as a
bias, so the shared bias of the two is nowhere in the data: English is carried
under `Coexistence` alone — it prefers short parallel units where German
nests, and on that one axis it is a usable, if mild, lens for a German input.
The one machine-readable trace of the idea is the `baseline` tag, and it sits
on German alone.

The German entry is the exception that makes this readable: its `themes` name
the axes it *imposes*, not ones it opens up. Adding the causal axes to English
to "complete the pair" would therefore be wrong — it would make English surface
as a lens for causality, which is the opposite of the point.

## Generating seed.sql

`src/seed.sql` is generated from the tables above. This file also feeds
`additional_docs/lat_facets.md`. Run both generators after editing it:

```
python tools/gen_seed.py
python tools/gen_facets.py
```

- Both tables land in **one** SQL table, `patterns`, discriminated by `kind`
  (`language` for `## Languages`, `form` for `## Forms`); the primary key is
  `(kind, name)`.
- Cells map to columns **by name, not by position** — the markdown order is
  `name, category, classification, focus, feature, description`, the insert
  order is `kind, name, description, focus, category, …`.
- `tags` and `themes` cells are comma-separated → JSON arrays (an empty cell
  becomes `[]`).
- `themes` values are validated against the closed vocabulary above; an unknown
  axis aborts generation rather than reaching the database.
- Never edit `src/seed.sql` or `additional_docs/lat_facets.md` by hand; both
  are overwritten on the next run.

`src/seed.sql` is embedded into the binary with `include_str!`, so regenerating
it changes nothing until you `cargo build` — and the seed is only applied to an
empty database, so the database file has to be deleted before the new data can
take effect.
